# Qoder / WorkBuddy 移植审查

日期：2026-10-29。对照来源：`../CLIProxyAPI-freetier2api-plugin`（`e90609d`）。

本轮覆盖协议转发、流式错误和用量、模型目录、账号参数、登录票据、凭据脱敏、
签到、全部 WorkBuddy 任务族、排程及管理页面。下表中的问题均已修复，并增加回归覆盖。

| 问题 | 修复及验证重点 |
| --- | --- |
| 旅行、开学季、夜间任务和连登流程吞掉错误，部分完成也可能报告成功 | 保留执行错误和已完成步骤；尚未确认计分返回 pending；已完成的开学季任务直接领奖，避免重复模型调用 |
| 排程使用完成时间，跨时段可能漏跑；执行与记录分离可能重复操作 | 在账号锁内重新读取配置和状态，执行前持久化对应时段；保存失败不调用上游；复用 Redis / PostgreSQL 锁协调多实例 |
| Qoder 模型上下文和默认输出上限遗漏，模型能力同步字段不匹配 | 读取嵌套默认上下文及输入上限回退；映射原生上下文、推理和模态字段；保留目录与积分倍率（包括显式 0）；WorkBuddy 静态回退保留能力信息 |
| 登录票据在创建校验失败时提前失效 | 创建期间独占预留票据，失败归还，成功消耗；重新授权在凭据保存成功后移除会话 |
| Qoder 的认证、限流及流内业务错误可能误重试，连接重置反而漏重试 | 区分流内业务错误与真实 HTTP 故障；401 / 403 / 429 不走瞬时重试；包装的 EOF / reset 可重试；内容审核和参数错误作为请求错误返回 |
| 切换账号、关闭窗口或放弃登录后，旧请求仍可能更新界面或打开授权页 | 登录发起、轮询和管理操作均校验请求所属代次，丢弃过期结果 |
| 签到错误可能误判成功或绕过刷新 | “already expired” 不再匹配“已签到”；Qoder 的 401 可进入网关续期路径；签到请求有时限 |
| 多层数组中的凭据没有完全脱敏 | 任意嵌套对象 / 数组递归脱敏，保留配置状态，不修改原始数据 |
| 无效代理、重定向和过大响应处理不完整 | 无效账号代理直接报错；不跟随重定向转发凭据；JSON 和刷新响应严格检查状态及大小 |

指纹净化规则、WorkBuddy 默认提示词和能力种子、Qoder 请求模板均与来源文件逐字节一致。
净化回归覆盖默认开启 / 每账号关闭、`content: null` 的工具消息、完整工具参数 JSON、
嵌套字符串、大整数精度及图片保留。适用范围仍为 WorkBuddy，Qoder 不增加文本净化。
新增自动任务和自动续期仍默认关闭。

验证结果：

- 后端 `go test -tags=unit ./...` 通过；最终 Qoder 错误处理补充通过包内竞态测试和反代集成回归。
- 反代适配器与服务的针对性 `-race` 检查通过。
- 前端串行完整测试：386 个文件、3016 个用例通过。
- Vue 类型检查、改动组件的 ESLint、前端生产构建和 Go 服务构建通过。
- `git diff --check` 通过。

验证使用本地模拟上游，没有登录或调用真实 Qoder / WorkBuddy 账号，也没有部署。
真实机器令牌的活动资格、账号所属区域、企业权限与当前上游活动可用性，仍需实际账号联调确认。

## 外部 Agent 的 Qoder 提示词

移除来源插件在缺少 system 消息时补入捕获 CLI 提示词的回退逻辑。
Qoder 仅转换客户端消息，不添加默认身份、环境或工具指令；原始模板只提供协议字段，
工具仍以客户端声明为准。developer 消息不会触发补入 system 提示词，也不替换为中性提示词。
新增回归覆盖仅 user、自定义 system、developer、空 system 与空消息，
并验证实际出站请求不带模板消息、三种网关入口不添加默认指令。
本地模拟验证无法确认上游服务端是否另行添加指令。

## 账号列表的反代额度

修复额度查询仅出现在管理面板、账号列表用量列没有反代分支的遗漏。
Qoder 套餐与拓展包、WorkBuddy 个人 / 企业积分使用既有额度接口与持久化快照，
展示已用、总额和剩余；全零 Free 套餐不丢失，不伪造总额为 0 时的比例。
Qoder 毫秒到期时间归一化为 Unix 秒，前端兼容旧快照。
列表支持单行查询和全局手动刷新，并限制并发、合并同账号请求、复用缓存，
失败保留历史数据，切换账号后丢弃旧响应。
本轮相关前端与语言 / 页面回归共 93 个用例通过，Vue 类型检查、ESLint、Qoder 包竞态测试通过。
