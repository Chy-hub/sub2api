# USTC 账号调度

本文描述本分支当前实现。上游实测、限制和推导见 [USTC 上游限流实测与调度设计](USTC_UPSTREAM_DESIGN.md)，脱敏记录见 [实测 JSON](ustc-upstream-probe-2026-10-02.json)。

仅对主机名为 `api.llm.ustc.edu.cn` 的 OpenAI API Key 账号启用 USTC 容量准入。TPS 和 3h/12h/24h 金额额度窗口继续保留。其他上游不使用这套窗口；Anthropic 原有的账号 RPM 行为保留，个人分支此前扩展到普通 OpenAI API Key 的手填 RPM 已撤销。

## 自动限制与界面

- `/key/info` 自动提供 `rpm_limit` 和 `max_parallel_requests`，复用现有后台额度刷新并保存到账号 Extra；`/user/info` 继续补齐用户级金额窗口。
- USTC 创建和编辑页面不再要求填写 RPM、粘性缓冲或并发。旧配置即使还保存在数据库，也不作为 USTC 准入依据。
- 账号页只读显示自动 RPM/并发上限、已提交请求数、活动并发、当前可准入数、窗口或保守同步期限。满额时显示等待 RPM 或并发，错位时显示等待同步/单请求验证。分组容量按物理 Key 去重汇总，并与账号页使用同一共享状态。
- 未知限制显示未知并阻止新转发；只有上游明确返回 `null` 才表示该项不限额。缺失、异常或数值零不等价于无限。刷新失败或返回缺少限制时保留最后有效配置。

额度快照有效期为 30 秒；冷账号和过期快照后台刷新，探测失败退避 5 秒。已有有效限制时，网络刷新不占用账号槽位。升级后即使金额快照尚新，缺少自动限制也会立即触发首次获取。金额窗口的 `budget_reset_at` 不用于 RPM 重置。

## 按 Key 共享的 60 秒窗口

实测上游采用约 60 秒固定窗口，锚定第一单实际准入，不按自然分钟清零，也不是请求逐个过期的严格滚动窗口。本地状态保存在 Redis，所有转移使用 Redis 服务端时间。

共享范围是 API Key 的 SHA-256 指纹：重复导入、同一 Key 加入多个分组、多个实例和重启都复用同一份容量。指纹只用于内部状态，不通过容量接口暴露；更换 Key 使用新状态。

一次实际上游尝试按以下生命周期处理：

1. 选号时原子预占一个 RPM 和一个共享并发租约，尚不建立窗口。
2. HTTP 发送前再次核验预占，提交后才开始窗口和已用计数。内部重试重新取得票据，每次真实发送都计数。
3. 未发送就取消、重选或终检失败时退还预占；即使转发使用 detached context，提交仍检查原请求是否已取消。普通已发送失败仍占 RPM。仅已确认发生在 RPM 记账之前的 `key_model_access_denied` 403 退款；它不会锚定空窗口。
4. 并发在响应体关闭时释放；长流跨越 RPM 窗口仍占并发，租约持续续期。已提交的转发可以继续完成计费，客户端断开不能提前释放其上游并发。进程退出后租约到期清理。
5. 正常成熟窗口到期时清除旧 RPM 使用量，保留活动长流。下一次实际提交才建立新窗口。

非流式响应中的 RPM 上限/余量用于校准。反馈携带窗口代次和提交次序，只收紧当前容量；较晚提交和未提交预占继续计入，迟到回包不能增加可用额度。上限调低立即生效，当前窗口内调高不抹去已用量。

## 首次同步与 429 恢复

| 状态 | 准入行为 |
| --- | --- |
| `ready` | 按剩余 RPM 和并发原子准入 |
| `sync_wait` | 等待上游提示的保守期限，停止新提交 |
| `verify_one` | 只放行一单验证；并发仍受活动长流约束 |
| `unknown` | 自动限制或共享缓存不可用，阻止新发送 |

上游 RPM 429 的 `Retry-After` 和 `reset_at` 是保守重试提示，实测会随拒绝时间后移，不能作为以后所有本地窗口的固定边界。有多个有效提示取较晚者；`reset_at` 与 `Date` 一起用于换算相对时差。无有效提示时保守等待完整 60 秒，删除了原来 3 秒重试冷却。

到期只让一单真实排队请求验证。验证成功后继续本地窗口；仍为 429 则重新按提示等待。旧窗口长流仍运行但并发有空位时，可以执行这单验证。权限拒绝不能证明窗口恢复，也不把整个账号置为权限故障。

Redis 没有该 Key 的可信窗口时，优先用一单真实非流式请求校准。USTC 的 SSE 成功响应缺少余量头，因此首次需求若为可重放的 Chat Completions 流式请求，会先发同模型的极短非流式校准（`max_tokens=1`），计入 1 RPM，再转发用户请求；校准内容不会发给客户端。其他无法校准的入口保守等待完整窗口后继续。已知冷却结束时用真实请求恢复，不周期性发健康探测。

明确金额预算 429 沿用额度门和预算复查，与 RPM 错位分开处理。已知较长冷却不会被较短提示覆盖；本地容量否决生成的 429 有内部标识，不反过来当成上游错位。

## 均衡与有界等待

同模型资格、同显式优先级和费用偏好的 USTC Key，优先选择 `(已提交 + 预占) / RPM 上限` 最低者，同值轮询；不存在额外粘性 RPM 缓冲。三个 20 RPM 的独立 Key 可用容量约为 60 次/分钟，持续超出容量不能靠调度增加上游额度。

每个进程的每个池使用一个协调器：队列按进入顺序派发，绑定到繁忙 Key 的续接请求不阻塞能使用其他 Key 的请求。请求等待时不占账号槽位、不预占 RPM。释放并发、退款和元数据刷新唤醒协调器；窗口使用最近恢复定时器，跨实例变化由每池合并的检查兜底。已删除每个等待请求每 200ms 重跑选号的轮询。

复用 `fallback_wait_timeout`（默认 30 秒）、`fallback_max_waiting`（默认 100）和 Redis 跨实例等待许可。队列满、超时或共享缓存不可用返回 429、`gateway_account_limit` 与 `Retry-After`。若所有候选已提交用完 RPM，且最早恢复超出请求等待预算，及时拒绝；仍有可退款预占或可释放并发时允许有界等待。

`previous_response_id` 始终保留物理 Key 绑定，不能因满额迁移。纯 USTC 池不受 OpenAI 实验调度开关影响；默认混合池仅均衡 USTC 成员，非 USTC 粘性等待保留。实验混合池保留原评分，但 USTC 转发始终经过共享硬准入。USTC API Key 不支持 Live，原生非 USTC WebSocket 路径不使用此准入。

成员列表仍包含冷却中的 USTC 账号，按需读取数据库并缓存 2 秒，恢复不依赖通用调度快照的全量重建。账号页关闭通用自动刷新时，继续每 30 秒同步已落库的 USTC 行；页面隐藏或弹窗打开时暂停。

## 验证与边界

定向测试覆盖三 Key 的 60 次并发分配、重复 Key 共享、取消/退款唤醒、续接绑定、冷流式校准、恢复验证、窗口跨越、长流租约、元数据未知/失败以及响应乱序。Redis 原子状态机使用 miniredis 验证；UI 测试覆盖自动限额、未知与无限区别、满额状态和编辑入口。

实测只有一把上游 Key，未在真实上游压测三账号池。管理端独立模型测试、curl 和其他客户端若共享同一 Key，也会占用上游容量；现有接口不提供完整调用记录和精确窗口起点，无法绝对镜像，会按反馈收紧容量并进入保守同步。首次响应的网络时间误差采用响应确认后的保守边界，可能牺牲少量吞吐。
