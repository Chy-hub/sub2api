# USTC 账号调度

本分支通过账号 `base_url` 的主机名识别 `api.llm.ustc.edu.cn`。OpenAI API-key 账号在关闭 OpenAI 实验调度策略时使用 USTC 专用均衡策略；其他主机保留原调度行为。混合分组内也可以使用该策略。

## 分配与 RPM

同优先级、同费用偏好的 USTC 账号优先选择当前分钟请求数较少的账号，相同计数随机打散。Claude Code 的相同会话不会一直固定到一个 USTC 账号。

绿区账号先使用，只有没有可立即准入的绿区账号时，才尝试原粘性账号的额外缓冲。基础 RPM 为 20、手动缓冲为 5 时，普通请求最多使用 20，粘性兜底最多使用 25。缓冲留空使用基础 RPM 的 20%，最少为 1；`sticky_exempt` 允许粘性请求超出基础 RPM。

RPM 使用 Redis 服务端时间按自然分钟计数。选号时原子预留，排队计划在获取槽位后预留；准入前放弃会退还，转发后即使上游失败也计入请求数。准入时 RPM 或额度发生变化而被否决，单请求最多经历 3 次此类否决；若账号池提前耗尽，同样返回 429、`gateway_account_limit`，避免遍历整个账号池逐个排队。Seedance 与其他 HTTP 入口使用相同准入规则。

`previous_response_id` 需要复用保存响应状态的账号，该路径保留续链绑定，但也检查当前额度并进行 RPM 准入；USTC API Key 不支持 Live，不能进入 Live 创建路径。

开启 OpenAI 实验调度策略后，均衡和原子预留由现有高级调度路径替代，RPM 仍采用该路径原有的检查及成功后计数方式；USTC 额度资格检查仍生效。原生 WebSocket 准入保留原有调度行为，不使用 HTTP 的 RPM 预留。

## 用量窗口与界面同步

调度候选账号的 `/key/info` 额度快照有效期为 30 秒；缺失、过期或已耗尽窗口到达重置时间时按需刷新，必要时同时查询 `/user/info`。同一进程的同账号并行刷新合并为一次探测；失败后保留已有快照并退避 5 秒。刷新成功后写入 `upstream_userinfo_` 字段，已知失效、过期或未重置的耗尽窗口会阻止调度；未知用量不据此阻止调度。

刷新结果按时间顺序合并，选号快照不会覆盖完整账号中时间相同或更新的额度快照。快照更新时间未知时，只在目标也没有可识别的更新时间时覆盖。

账号页面显示 USTC OpenAI API Key 行且通用自动刷新关闭时，每 30 秒读取已落库的账号数据，只同步当前列表中这些行，不触发上游探测或刷新今日统计。页面隐藏、弹窗打开或列表正在加载时暂停；通用自动刷新开启时使用用户设置的列表刷新间隔。

## 当前限制

冷账号或过期快照的调度刷新在抢槽之前进行，最坏情况下探测超时为 35 秒；候选先排序，再按实际选择需要刷新，不会为了比较候选而同步探测整个账号池。抢槽后的终检只读取当前快照；若此时已过期，则释放并发槽位、启动共享后台刷新并按重选预算重试。请求取消会停止本请求等待，共享探测继续完成并保存结果。

快照缓存和刷新合并以进程为范围，多实例可能分别探测和落库。缓存最多保留 4096 个账号，5 分钟未访问的条目按 LRU 增量清理。识别 USTC 池所读取的列表复用于后续选择；非 USTC 的有效粘性命中保留原来的快速路径。用量耗尽只按已知的精确窗口花费达到限额判断，不使用舍入后的百分比或余额。

| 3 | 报告场景不成立：USTC API Key 不具备 Live 能力。增加路由回归验证，保留既有 Live 实现。 |
| 4 | 保留已确定的默认调度范围。实验调度继续使用原评分与 RPM 记账；新增额度门覆盖其续链及终检。 |
| 5 | 复用 USTC 检测所取列表；非 USTC 有效粘性命中不增加列表查询，也复用已读取的绑定账号。 |
