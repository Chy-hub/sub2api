## 清理和边界检查

- 移除无调用的 CaptureEnabled、RealFallback、ImportUsage/ImportRecentUsage、FallbackApplied/FallbackWindowSeconds、恒真页面分支及对应接口字段；修正 HourlyMetric 和 DayCount 注释。
- 不再读取 `capture_since`。旧数据库中的该兼容列和预算空表保留，不做破坏性清理，也没有启用或自动删除逻辑。
- 探针只允许指定 USTC HTTPS 主机和默认/443 端口。上游同名响应头不能伪造本地准入标记；标记使用本地私有响应体类型。
- 裸 JSON 行先于 SSE 字段冒号解析，补充回归；维持事件和 body 的大小限制，不记录正文或凭据。
- Cron 不使用间隔抖动；表单明确全天语义并防止全不选星期。API 中旧空星期仍表示每天，保持兼容。
- Responses 请求不发送不支持的 `stop`/`seed`；保留协议支持的 `temperature`/`top_p`，不盲目删参。
- 原报告“Stop 不等待 persist”不适用于当前实现：persist 同步运行于任务 goroutine，Stop 取消任务后等待其 WaitGroup；本次未增加异步写入。
- 长度未知文案独立命名；使用记录 TPS 按当前界面 locale 格式化，并防御非流式首字值。

## 查询规模验证

使用临时 PostgreSQL 18 集成环境，生成 50,000 条原始使用记录、10 个模型，覆盖约 174 天；没有调用上游模型。完整请求包含 summary、趋势、小时折叠、两期统计、分布和长度分组。直接调用 repository，结果不经过服务缓存。

| 场景 | JSON 投影版本 | 直接数值列版本 |
| --- | --- | --- |
| 最近 24h 趋势和小时图（288 条） | 41 ms | 10 ms |
| 180 天完整分析（50,000 条） | 7.662 s | 619 ms |

以上为本机单轮实测，不代表 NAS、百万级数据或冷缓存性能。365 天历史查询也验证成功。`EXPLAIN (ANALYZE, BUFFERS)` 用于检查源过滤和指标聚合；全范围读取时顺序扫描合理，未据此新增冗余索引。长历史仍有精确分位数计算成本，通过短缓存、取消、超时及分析并发限制控制开销，不限制原始数据保存。
