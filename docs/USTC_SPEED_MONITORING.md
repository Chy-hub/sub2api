# USTC 速度观测

## 分析的边界

这个功能分析已经存在的速度、首字和 token 数据。真实调用只从 `usage_logs` 同步，不在网关增加采集，不保存真实提示或回答。基准检测保留原有合成请求和测量能力。

设计先回答实际问题，再决定展示形式：

| 问题 | 展示与用途 | 防止误解的条件 |
| --- | --- | --- |
| 何时开始变慢，持续多久 | TPS / TTFT / 阶段时间趋势，原始点或时间桶统计 | 时间轴固定到已选范围；缺失不补零；真实聚合用柱，原始调用用散点，基准用线 |
| 最近是否比以前慢，慢多少 | 主图切换“周期对比”，并列平均值、P50、慢速尾部和变化百分比；两段时间从各自起点对齐 | 模型与来源分开，同一账号/调用条件筛选应用于两个周期；当前未结束的日期只比较对应已过去部分 |
| 平均看起来快，是否仍经常遇到慢调用 | 主图切换“分布与波动”，相同区间的调用占比直方图、P10 / P90 慢速水平与波动系数 | TPS 用 P10 看慢速，等待用 P90 看慢等待；占比而非绝对条数避免请求量差异主导图形 |
| 哪些小时观测表现更好 | 现有调用时段分布将所选范围按本地小时折叠，独立选择生成 TPS 或端到端 TPS | 多天原始调用合并统计，显示有效调用数和覆盖天数；曲线连接有数据的小时，不给缺失小时制造观测 |
| 均值变化是否伴随任务构成改变 | 周期对比中折叠的输入 / 输出长度构成表：两期占比、桶内均值变化 | 使用现有 token 字段；只辅助核对可比性，不把长度与速度的相关性解释为原因 |
| 哪个模型的变化值得继续看 | 周期对比下方同模型、同来源的前后比较表，点击选择主图对象 | 不将不同模型的混合平均当作平台性能变化，也不自动生成跨任务的“性能评分” |

没有另加调用明细页面、账号权重模式、任务总耗时排名、人工综合分或额外采集字段。单次总耗时由任务长度决定，保留在原记录和基准详情中，主图不再提供这一选项。

## 页面与统计

侧栏只有“速度观测”主入口，内部收纳“趋势分析”和“检测任务与配置”。主体保持 TPS / TTFT / 阶段时间图，使用“分析视角”下拉切换趋势、周期对比、分布与波动，不为每个分析增加标签页。

时间选择沿用使用记录的 `DateRangePicker`：按所选时区解释日历日期，结束日包含在内；“最近 24 小时”使用精确滚动窗口。日期应用后联动趋势、时段图、对比和导出。主应用按钮会提交选择器中尚未应用的日期。

所有统计都是：先筛选模型、来源、账号、日期及高级条件，再对有效原始调用计算。每个调用权重相同。选择一个账号就分析它的调用，选择多个账号就合并所选调用；不先算账号均值再平均。失败、取消、跳过和缺失指标不作为零速度加入分布。

周期对照支持上一等长时段、上周同期、上月同期、去年同期和不对照。月份和闰年从合法的对应起始日开始，保留窗口的日历长度；时区和夏令时按本地日期计算。图中明确显示实际两个窗口。历史没有数据就留空，不补测过去时段。

对比图最多约 120 个时间桶，并从原始调用计算各桶统计；卡片、直方图和长度构成使用整个过滤范围，不受原始趋势最多 5,000 个点的返回限制。分位数直接计算，不平均已经聚合的均值或 P50 / P90。

新增周期 / 分布分析的中位数至少需要 5 个有效调用；慢速尾部和波动系数至少需要 20 个；均值变化至少需要两期各 5 个有效调用。界面明确提示样本不足，并说明这些只是展示门槛和观测差异，不是统计显著性保证。波动系数为总体标准差 / 均值，不能跨不同指标、来源和任务构成直接比较。

周期对比的调用构成表默认折叠，仅在需要解释差异时展开。输入桶是 `<1K`、`1K–4K`、`4K–16K`、`16K–64K`、`64K+`；输出桶是 `<128`、`128–512`、`512–2K`、`2K–8K`、`8K+`。K 表示 1024，区间左闭右开，未知单列。

## 指标的实际含义

- 真实生成 TPS：`输出 token × 1000 / (总耗时 − 记录首字时间)`，只对首字和输出计数有效的流式记录提供。它是近似生成速度，不是精确逐 token 计时。
- 端到端 TPS：`输出 token × 1000 / 总耗时`。它包含首字等待，任务输出长度会影响该指标，比较时可核对长度构成。
- 真实首字：使用记录的 `first_token_ms`，不能据此区分思考与正文，也不能分解成网络、排队、预填充的独立耗时。
- 基准首字 / 首次有效输出：来自基准的事件测量，保留正文与含思考的区别；与真实记录始终按来源分开。
- 响应头、输出停顿和末次输出后等待：只有基准事件数据支持，真实调用不展示这些不可观测选项。

真实使用记录不提供可靠失败状态，所以不从它推导平台成功率、可用率或 429 故障概率。真实样本使用 `recorded` 状态。基准的成功、限流、跳过和失败分别保留。

## 数据同步与保留

后台每 5 分钟从既有 `usage_logs` 同步最近 24 小时，以 `legacy_usage_id` 去重；首次或升级后从功能启用时间补齐，历史导入另外分批回填。旧的网关被动采集真实样本留在表中，但不参与查询，避免重复计数。

样本长期保留，不设保留天数，不设置每日检测请求 / token 预算。新分析不增加表、迁移或真实调用采集字段。正常趋势查询不请求详细分析，切换对比 / 分布时才计算。

## 检测任务、空闲误判与约束设置

每轮选定模型和合成请求，对不同物理 Key 并行发起；同一物理 Key 后台并发最多 1。任务编辑器提供检测间隔（秒 / 分钟 / 小时）、cron、活动时段、账号、模型、输出参数、超时、并行和起跑差，以及用户负载、RPM / 并发预留和 429 缓测 / 暂停策略。启用任务尽快执行首轮，任务列表每 10 秒刷新。

任务编辑器提供持久的“忽略任务约束”设置，适用于后续定时与手动运行。开启后跳过任务的活动时段 / 星期、账号并行数、起跑差、后台检测并发保护、用户排队保护、RPM / 并发预留、活动请求上限和额外 429 退避 / 暂停；保留目标、生成参数、超时和触发频率。账号实际 RPM / 并发、模型权限、额度与共享准入属于正常模型调用限制，继续生效。此设置保存为任务 JSON 的 `ignore_task_constraints` 字段，旧任务默认关闭。

低优先级检测的排队判断使用共享 Redis 等待租约索引，与等待的获取 / 释放原子更新，按 Redis 时间清理过期租约。旧的有界 SCAN 会在遍历大量无关键后把“尚未遍历完”误判成“有人排队”，现已移除该判断。

任务显示具体跳过原因：用户正在等待、RPM 预留不足、并发预留不足、共享容量冷却、账号额度阻塞、活动请求上限、数据读取失败、起跑差过大等。读取失败仍保守跳过，不能伪装成空闲。

基准因负载或 429 暂停时，可按原配置显示最近真实调用，并明确标记来源和数据年龄。这种短时回退不参与所选历史基准的周期分析。

## 验证重点

1. 不均衡的账号调用量仍按调用等权；单账号筛选正确。
2. 当前未结束日期、滚动窗口、月末、闰年和夏令时下的对照范围正确。
3. 超过 5,000 个原始点仍使用完整样本计算对比和分布。
4. 实际浏览器中分类横轴已注册，稀疏时段可见曲线，空数据不补零。
5. 大量无关 Redis 键不阻断空闲检测，真实用户等待及过期 / 释放租约判断正确。
6. 任务约束开关可持久保存；开启后定时与手动运行都跳过任务附加约束，无法绕过正常模型调用限制。
7. 页面只使用本地夹具、数据库和模拟上游回归验证，不消耗真实模型请求。
