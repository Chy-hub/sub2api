# 基准测试与使用记录速度分析

## 页面职责

- **使用记录 → 速度分析**：在“用量明细”旁切换，直接分析当前筛选下的真实调用。
- **基准测试**：侧栏直接进入，专门观察上游服务的速度和稳定性。页面按筛选、主图、检测任务、辅助设置组织；任务在当前页编辑，无独立任务导航。

两处主图只提供 TPS 和 TTFT，支持时间趋势、周期对比和分布与波动。Time、总耗时、首字后耗时和阶段耗时不再作为趋势指标。

## 保留原始记录，聚焦速度分析

每次基准检测仍记录输入 / 输出 token、首字、整体及阶段耗时、输出停顿、状态与结束原因等既有测量。详情和 CSV / JSON 导出保留这些字段。输出 token 继续用于计算 TPS；不删除或缩减记录，也不把 token 数量、任务总耗时作为上游服务能力的评分。

检测任务负责定义合成请求、目标账号 / 模型和运行计划。基准结果聚焦 TPS、首字等待、波动、错误和限流；不增加任务能力评测、任务长度构成分析、配置分组曲线或配置变化评分。

输入长度和测试参数本身也会影响观测结果，TPS / TTFT 不能直接换算为服务器负载百分比。这里只在配置中说明测试条件，参考 [NVIDIA 的推理性能指标说明](https://developer.nvidia.com/blog/llm-benchmarking-fundamental-concepts/)，不另建条件分析功能。

## 数据来源与筛选

真实调用分析直接查询 `usage_logs`，没有后台复制、导入等待或网关新增采集。沿用使用记录的时间、模型、用户、API Key、账号、分组、请求类型、压缩、计费类型 / 模式和模型不匹配筛选。模型维度与用量明细一致，按请求模型匹配。

基准接口固定查询 `source=probe`。暂停、跳过或没有观测时显示缺测与原因，不用真实调用替代基准结果。旧真实样本保留在数据库中，但不用于这两个入口的分析；没有迁移或删除已有记录。

使用记录的日期选择与筛选直接驱动速度分析；基准页使用同款日期选择器，支持日历范围和精确最近 24 小时。图表横轴固定到应用后的窗口，切换范围会更新趋势、时段图和比较。

## 速度与首字口径

- 真实生成 TPS：`输出 token × 1000 / (总耗时 − 记录首字时间)`，仅对有效的流式记录提供。这是沿用使用记录数据的近似速度。
- 真实端到端 TPS：`输出 token × 1000 / 总耗时`，包含首字等待；非流式记录可提供该指标。
- 真实首字：使用既有 `first_token_ms`，不能区分思考与正文，也不能拆出网络、排队和预填充耗时。
- 基准首字 / 首次有效输出：保留事件测量的正文和含思考输出口径，单次详情中可查看原始测量。

使用记录不提供可靠的失败状态，速度分析不由它推导上游成功率或可用率。基准成功率和 429 率只统计实际发起的成功、错误和上游限流；跳过不作为上游失败。

## 分析展示

| 视角 | 回答的问题 | 统计方式 |
| --- | --- | --- |
| 时间趋势 | 什么时候变慢、是否持续 | 真实聚合用柱，原始观测用散点，基准聚合用线；缺失不补零 |
| 周期对比 | 相对之前，平均和慢速表现变化多少 | 相同筛选作用于两期，按各自起点对齐；当前未结束的日期只比较对应已过去部分 |
| 分布与波动 | 均值是否掩盖慢调用，观测是否分散 | 同区间占比直方图、P50、TPS 的 P10 / 等待的 P90、标准差 / 均值 |
| 调用时段分布 | 哪些小时观测更快 | 按所选时区将多天调用折叠到小时，显示有效样本与覆盖天数 |

统计先筛选，再将有效调用等权计算；账号仅作为筛选，不先算账号平均再平均。模型分开，失败、跳过和缺失指标不补成零速度。

周期对照支持上一等长时段、上周 / 上月 / 去年同期及不对照，明确显示实际窗口。月份、闰年和夏令时按所选时区处理。基准不返回任务长度分桶分析；真实调用可在折叠区核对既有输入 / 输出长度构成，以辅助理解两期真实工作差异。

卡片和分布使用完整过滤范围，独立于原始趋势最多 5,000 点的返回限制。分位数从原始调用计算，不平均已经汇总的均值或分位数。新增周期 / 分布视图的中位数至少需要 5 个有效调用，慢速尾部和波动至少 20 个；这些展示门槛不是显著性保证。

## 检测任务与运行约束

任务编辑器保留目标账号 / 模型、合成提示、输出参数、思考模式、超时、检测间隔 / cron、活动时段、并行、容量预留及 429 退避等设置。检测频率直接使用秒 / 分钟 / 小时输入，启用后尽快执行首轮，任务列表定期刷新。

“忽略任务约束”是持久的任务设置，对定时和手动运行生效。开启后跳过任务额外的活动时段、并行数、起跑差、后台检测并发保护、用户排队保护、容量预留、活动请求上限和额外 429 退避 / 暂停。检测目标、请求参数、频率和超时仍保留；实际模型权限、账号额度、共享 RPM / 并发准入继续生效。

普通模式的排队保护使用跨实例共享等待租约，获取 / 释放时原子更新，按 Redis 时间处理到期；大量无关 Redis 键不会再被误判成排队。

原始检测数据长期保留，不按天数自动删除，不增加每日请求 / token 预算。
